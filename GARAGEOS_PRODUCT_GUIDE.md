# GarageOS: функции, проверка и дальнейшие улучшения

**Актуальность:** 07.10.2026  
**Проверки:** 114 backend-тестов, 1220 assertions; TypeScript и production build проходят; `composer validate` успешен, `composer audit` чистый. Все 34 локальные SQLite migrations применены; MySQL/MariaDB staging gate не пройден.

> Этот документ описывает реализованное состояние кода, а не обещанный roadmap. В таблицах UI отдельно отмечены действующие действия и элементы, которые пока выглядят как кнопки, но ничего не делают.

## Что можно тестировать сейчас

### Запуск локально

В `GarageOS-app` используйте локальную SQLite-конфигурацию, описанную в [RUN.md](GarageOS-app/RUN.md). Для первого запуска нужны PHP 8.3+, Composer и Node.js:

```powershell
cd .\GarageOS-app
composer install
npm ci
Copy-Item .env.example .env
```

В локальном `.env` задайте `APP_ENV=local`, `APP_DEBUG=true`, `APP_URL=http://localhost`, `DB_CONNECTION=sqlite`, `DB_DATABASE=database/database.sqlite`, `MAIL_MAILER=log`. Затем:

```powershell
php artisan key:generate
New-Item -ItemType File -Path .\database\database.sqlite -Force | Out-Null
php artisan migrate
php artisan photos:secure-migrate
php artisan serve
```

Во втором терминале:

```powershell
cd .\GarageOS-app
npm run dev
```

Откройте `http://127.0.0.1:8000`. Для публичного read-only демо сначала загрузите fixture-данные:

```powershell
php artisan db:seed --class=DemoSeeder
```

Затем откройте `http://127.0.0.1:8000/demo`. Не запускайте demo seeder на рабочей базе без предварительной проверки его назначения.

### Ручные сценарии

| Сценарий | Что сделать | Ожидаемый результат |
|---|---|---|
| Регистрация и trial | Открыть `/register`, создать организацию и войти | Создаются организация, owner, Start trial на 14 дней, настройки `Asia/Almaty` и `KZT` |
| Быстрый старт | Пройти пункты onboarding на Dashboard | Прогресс меняется после добавления услуги, сотрудника, клиента, автомобиля и заказа; блок можно скрыть |
| Клиент и автомобиль | В `Клиенты` заполнить формы нового клиента и автомобиля | Автомобиль связывается с клиентом; карточка клиента и автомобиля показывает tenant-scoped данные |
| Запись и конфликт | Создать заявку, выбрать услугу/мастера/время; проверить интервал занятого мастера и перенести запись в недельном виде клавишами/свайпом | Окончание подставляется по длительности услуги; inline-проверка показывает конфликт; сервер повторно валидирует; перенос сохраняет время и длительность |
| Заказ и Kanban | Создать заказ из заявки либо через форму «Новый заказ»; добавить работу; переводить этапы | Сумма рассчитывается сервером; Kanban меняет статус только при допустимом переходе |
| Склад | Для Business добавить запчасть, поставить её в заказ, пройти этапы «В работе» и «Готов» | В заказе показываются свободный остаток и резерв; при готовности резерв списывается; ledger фиксирует движения |
| Платежи и долг | Для заказа добавить частичный платёж, второй платёж, затем отменить платёж | `paid_total` и `balance` пересчитываются сервером; отмена не удаляет платёж; действия попадают в Activity Log |
| Закрытие заказа | Попробовать закрыть заказ с ненулевым балансом; затем подтвердить `allow_unpaid` | Backend отклоняет закрытие без override; owner/manager может включить checkbox и подтвердить действие. Оба поведения покрыты тестами |
| Фото и клиентская видимость | Загрузить корректное/поддельное фото; открыть lightbox и листать; изменить подпись/категорию/видимость; архивировать | Поддельный файл отклоняется; staff управляет метаданными; архив soft-deletes запись без удаления private file; public/client stream недоступен для архива |
| Ссылка заказа | Создать ссылку в карточке заказа, открыть в приватном окне, перевыпустить и отозвать | Отображаются только client-safe поля и разрешённые фото; после отзыва старый токен не работает |
| Клиентский кабинет | В карточке клиента нажать «Открыть доступ»; пройти password reset link из локального `storage/logs/laravel.log` | Клиент после входа видит свои автомобили, историю, статусы и видимые фото; внутренние комментарии и себестоимость не передаются |
| Финансовый отчёт | Для Business записать расход, изменить, архивировать; переключить период и задать даты | Сервер отдаёт доход, расход, операционный итог, средний чек, должников и движения денег; архив не стирает историю |
| Уведомления | Открыть `/notifications`, отметить одну запись или все | Состояние read/unread сохраняется; Activity feed показывает журнал доступных событий |
| Лимиты и тариф | На Start запросить Business; в локальной среде Platform Admin подтверждает заявку с тестовым payment reference | Business включает склад, расходы и расширенные отчёты; downgrade блокируется при превышении числа сотрудников |
| Trial expiry / hard lock | Использовать `BillingLifecycleTest` либо тестовые даты подписки в изолированной среде | По окончании срока workspace блокируется; владелец видит экран подписки, менеджер — read-only экран; истечение фиксируется в журнале |
| SaaS Admin | Под Platform Admin открыть `/admin` и карточку организации | Видны метрики и организации; доступны review тарифных заявок, блокировка/разблокировка и продление trial. Полного user management/MRR нет |

Для безопасной проверки Business/Platform Admin в локальной базе нужен отдельный тестовый Platform Admin. Создавайте его только локально/в тестовой базе, не в production; для обычной регистрации пользователь становится owner Start и не получает Business-модули автоматически.

Создать локального администратора можно через `php artisan tinker`:

```php
App\Models\User::factory()->create([
	'name' => 'Локальный Platform Admin',
	'email' => 'platform-admin@example.test',
	'organization_id' => null,
	'role' => 'platform_admin',
	'status' => 'active',
	'password' => 'LocalOnly-ChangeMe-123!',
]);
```

Выйдите из owner-сессии и войдите этим пользователем, затем откройте `/admin`. Пароль в примере предназначен только для одноразовой локальной базы; не переносите его в production.

## Роли и доступ

| Роль | Что доступно |
|---|---|
| Owner | Dashboard, клиенты/автомобили, заявки, заказы, услуги, сотрудники, уведомления, настройки, подписка. Business-модули зависят от тарифа. Может включать клиентский кабинет и управлять тарифной заявкой |
| Manager | Операционная работа с заявками, заказами и клиентами; финансы/Business-модули — если их разрешает тариф. Не управляет настройками организации и подпиской |
| Mechanic | Назначенные заказы, рабочие статусы, безопасная информация по работам и уведомления. Нет доступа к полной финансовой информации, складу и администрированию |
| Client | Только `/portal` и выход. Видит связанные автомобили/заказы, статусы, доступные фото и финансовые суммы своего заказа |
| Platform Admin | `/admin`, организации, подписки и подтверждение тарифных заявок. Не является сотрудником tenant-организации |

## Что стоит улучшить в существующих страницах

### Удобство и полнота

- В карточке клиента/автомобиля связать все позиции с заказами и добавить явные tabs, историю и финансовую детализацию; быстрые действия уже добавлены.
- Добавить график рабочих часов/перерывов и вертикальную сетку календаря; текущая проверка доступности проверяет пересечение записей, но не business hours.
- Автоматическое переназначение активных заказов при деактивации сотрудника не выполняется; сотрудника нельзя отключить, пока заказы/будущие записи не переназначены.
- Добавить pagination/empty/error/loading/permission states и accessibility keyboard checks там, где сейчас отображается только базовое состояние.
- Выполнено 02.10.2026: authenticated browser smoke-check `/finance` и `/inventory`; обе страницы загрузились без ошибки. Finance показывает KPI/период/должников, Inventory — KPI, empty state и форму. Старые runtime ошибки соответствовали отставшей SQLite schema.
- Проверить на мобильных устройствах длинные таблицы, форму расписания и модальные шаги; основная адаптивная раскладка уже есть.

## Что ещё не реализовано или не подтверждено

### Обязательное перед платной установкой

- Реальный migration/integration smoke-test на MySQL 8 или MariaDB. Локальный suite использует SQLite `:memory:`; в текущем окружении MySQL/Docker не запущены.
- Развернуть staging с production-эквивалентом, запустить `migrate --force`, пройти заказ/оплату/фото/portal, проверить backup/restore и private photo migration.
- В production указать реальные APP_KEY, HTTPS/domain, DB credentials, SMTP, права storage, cron `schedule:run`, supervisor/systemd queue worker и алерты логов.
- Выбранный эквайринг и автоматические платежи/продление отсутствуют. Сейчас администратор вручную проверяет перевод и его reference.

### Функции GarageOS, которых пока нет или они неполные

- Публичная landing page с тарифами/FAQ; сейчас guest-flow начинается с login/register.
- Полный Client Portal: записи клиента, рекомендации, будущие напоминания и собственный раздел платежей; сейчас портал read-only для машин/заказов/фото.
- CRUD/archive строк заказа; изменение employee profiles/status уже доступно owner.
- Изменяемые пользователем статусы заказов; список status transitions пока фиксирован в backend.
- Детальная настройка прав по сотрудникам, филиалы и несколько складов.
- Автоматические email/SMS/WhatsApp уведомления/напоминания, онлайн-запись и online payments.
- Расчёт зарплат, бухгалтерские интеграции, внешний API, AI-автоматизация.
- Полный SaaS Admin для MRR/платёжной истории/выгрузок и управления пользователями; есть организации, блокировка/trial и review тарифных заявок.
- CI/CD pipeline и автоматические MySQL/MariaDB staging jobs.
- Все графики Dashboard, Analytics и Finance используют Bklit UI; дальнейшая интеграция выполняется через `@bklit` registry по skill `.agents/skills/bklit-ui`.

## Ограничения тестового окружения

- Feature tests используют SQLite in-memory; локальная миграция SQLite подтверждена, но это не заменяет MySQL/MariaDB migration check. В текущей проверке `127.0.0.1:3306` недоступен и Docker daemon не запущен.
- Для портала нужен реальный email клиента; в локальном `MAIL_MAILER=log` reset link можно искать в `storage/logs/laravel.log`.
- Проверка реального SMTP, платежей, scheduled cron и постоянного queue worker требует staging/production-like окружения.
- Demo и локальные test fixtures не являются production tenant данными; не проводить эксперименты в реальной организации.
